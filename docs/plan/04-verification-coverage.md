`rebuildPeaks`: each mode, **2,048 B** old retained + **13,312 B** build scratch + **44,056 B** grown retained = **59,032 B** measured peak. Warm replacement keeps **57,368 B** with no allocation. Counting resource excludes client containers. This is one controlled growth fixture, not a capacity formula.

Isolated allocation fixtures:

- `isolatedCapacity`: hard-capacity update needs two mutation records but has one. The rejected update leaves geometry, extent and handles unchanged; reserving only the second record makes it succeed. The prepared build/query probes undersize one workspace dimension at a time and reject without allocation, output writes or pair callbacks.
- `referenceGrowthFailure`: flat inserts grow entries without reference storage. With nodes and build workspace already ready, the first tree build fails its one reference allocation. Reserving only references allows the exact build to succeed under `failAll`. This tests an isolated growth failure rather than fabricating a hard-capacity reservation with fewer references than entries.
- `workspaceAllocationFailures`: grow `{entries=2, movedEntries=1, buildEntries=2}` to `{11,7,13}`. Ordinals 1–8 map to rank order, partner row, moved indices, membership, selections, descriptors, keys, and temp. Failure preserves the original buffer ownership and bytes; an ordered moved query and a prepared build reuse the old workspace without allocating. Retry grows all eight buffers.
- `crossPrefixes`: ordered convenience cross uses workspace ordinals 1–4 for order, row, membership, and selections (no moved/build buffers). Fail each allocation before the first callback, then retry to the exact handle-pair sequence.

## Index and entry-store allocation map

`indexBufferAllocationFailures` starts with eight coincident ranked entries, built with prepared scratch, a one-node topology and no retained mutation scratch (except the oversized shrink fixture). It checks the requested bytes and allocation trace at each 1-based ordinal, then retries the same operation. `moveOnlyBuildAllocationFailures` checks the same build sequence with a move-only payload in both modes.

| Operation | Local workspace buffers | Index buffers | Entry-store buffers |
|---|---|---|---|
| Insert ninth ranked entry beyond extent | — | 1 mutation keys, 2 mutation temp, 3 nodes, 4 references | 5 boxes, 6 payloads, 7 metadata, 8 slots, 9 rank cells |
| Update beyond extent | — | 1 mutation keys, 2 mutation temp, 3 nodes | — |
| Grow reservation | — | 1 nodes, 2 references, 3 mutation keys, 4 mutation temp | 5 boxes, 6 payloads, 7 metadata, 8 slots, 9 rank cells |
| Shrink a nonempty tree | 1 build descriptors, 2 build keys, 3 build temp | 4 nodes, 5 references | 6 boxes, 7 payloads, 8 metadata, 9 slots, 10 rank cells |
| Grow replacement: copy and move-only consume, default and transactional | 1 build descriptors, 2 build keys, 3 build temp | 4 nodes, 5 references | 6 boxes, 7 payloads, 8 metadata, 9 slots, 10 rank cells |

- `EntryStore::allocate` is shared by insert, reserve, shrink and grow replacement. It attempts all three dense arrays (boxes, payloads, metadata) even if one fails; no slot or rank request follows a dense failure. `testAllocationFailure` also exercises the standalone store.
- The index fixture checks that each failure preserves old buffer ownership, extent, active topology counts, entries, handles, query identities and output sentinels. Insert/update keep two newly grown mutation scratch buffers if a later allocation fails; retry reuses them. Other operations release every pending allocation. The consume fixture also verifies exact source pointee ownership before retry.

## Nonthrowing API checks

`nonthrowingApi` in [tests/index-test.cpp](../../tests/index-test.cpp) compiles in `index-test` and `index-test-noexcept`. It rejects payloads with potentially throwing move construction or destruction. Potentially throwing copies and move-only payloads reject copy insertion/build (including projected calls) but still accept rvalue insertion and consume builds. `int` is the positive copy control.

`insertWith`, `buildWith` and `buildConsumeWith` accept lvalue-only `noexcept` accessors returning `Box` or `Rect`, but reject otherwise equivalent potentially throwing accessors and non-geometry results. `forEachPairSelected` tests the left and right selectors independently, including a return type with throwing conversion to `bool`, and rejects a potentially throwing pair predicate. Existing `PairVisitor`/`CanVisit` assertions cover visitor rejection. The `Resource` virtual interface checks protect the `noexcept` specifications that forbid potentially throwing overrides.

[Release: 20/20](verification-nonthrowing-2026-11-20/ctest-release.log) · [ASan/UBSan: 5/5](verification-nonthrowing-2026-11-20/ctest-asan.log) · [libstdc++ debug: 14/14](verification-nonthrowing-2026-11-20/ctest-libstdcxx-debug.log) · [environment and tested hashes](verification-nonthrowing-2026-11-20/environment.txt). No seed or runtime changes.

## Reproduction

Run from the repository root. Use a local Box2D checkout at `178495ba35695aefe9c321e569d2277f06db3b90` for the benchmark-enabled builds below. A fresh build can omit the override and use the pinned CMake archive instead.

```sh
cmake -S . -B /tmp/qt-release -G Ninja -DCMAKE_BUILD_TYPE=Release \
  -DFETCHCONTENT_SOURCE_DIR_BOX2D=/path/to/box2d
cmake --build /tmp/qt-release
ctest --test-dir /tmp/qt-release --output-on-failure
/tmp/qt-release/tests/index-test

cmake -S . -B /tmp/qt-asan -G Ninja -DCMAKE_BUILD_TYPE=RelWithDebInfo \
  -DCMAKE_CXX_COMPILER=clang++ -DQUADTREE_BUILD_DEMO=OFF \
  -DFETCHCONTENT_SOURCE_DIR_BOX2D=/path/to/box2d \
  '-DCMAKE_CXX_FLAGS_RELWITHDEBINFO=-O1 -g -DNDEBUG -fsanitize=address,undefined -fno-omit-frame-pointer -fno-sanitize-recover=all'
cmake --build /tmp/qt-asan --target index-test index-test-noexcept entry-store-test entry-store-test-noexcept quadtree-index-fuzz
ctest --test-dir /tmp/qt-asan --output-on-failure \
  -R '^(index-test(-noexcept)?|entry-store-test(-noexcept)?|index-fuzz-quick)$'

cmake -S . -B /tmp/qt-stl-debug -G Ninja -DCMAKE_BUILD_TYPE=Debug \
  -DQUADTREE_BUILD_DEMO=OFF -DQUADTREE_BUILD_BENCHMARKS=OFF -DCMAKE_CXX_FLAGS=-D_GLIBCXX_DEBUG
cmake --build /tmp/qt-stl-debug
ctest --test-dir /tmp/qt-stl-debug --output-on-failure
```

Seeds: `randomized` uses `0x625f42`, `hardCapacity` uses `555`; entry-store defaults to `20240917` (rank variants also use +1/+2). `index-fuzz-quick` runs seeds 1–4, 400 steps, at most 120 entries, all supported types and scenes (fixed/outliers intentionally skipped). Its printed replay is `quadtree-index-fuzz --types=TYPE --scenes=SCENE --seed=S --steps=STEP_PLUS_1 --max-entries=N`. New probes use literal data and need no seed.
